- 화면 꺼짐/잠금/일반 대기/다른 앱 사용 중에는 한도를 늘리지 않고, 쿨타임 중 이용은 다음 주기에 적립하지 않는다.
- 일일 통계와 주기 한도는 별도다. 초기 초안은 채택하지 않았고 [Q1 답변](../QnA/00_질문과_답변_기록.md)에 따라 구현을 정정했다.

## 실행 검사 도구 간섭 분리
- 첫 실행의 System UI ANR과 두 번째 실행의 자동 화면 조회 간섭을 각각 실패 증거로 보존한다.
- XML 조회 없이 캡처한 화면에는 일반 대기가 정상 표시되었다. uiautomator dump 후 XML에는 대상 앱 본화면이 보였고, 직후 캡처에는 대기가 처음부터 재시작되어 검증 도구 간섭을 확인했다.
- [Android UiAutomation](https://developer.android.com/reference/android/app/UiAutomation#FLAG_DONT_SUPPRESS_ACCESSIBILITY_SERVICES)은 기본적으로 다른 접근성 서비스를 억제한다. [AOSP DumpCommand](https://android.googlesource.com/platform/prebuilts/fullsdk/sources/android-31/+/refs/heads/androidx-savedstate-release/com/android/commands/uiautomator/DumpCommand.java)는 해당 자동화 연결을 사용한다.
- 최종 실제 검증은 uiautomator dump를 사용하지 않는다. 화면 캡처와 확인된 버튼 좌표를 사용하고 실제 SQLite의 PENDING/OPENED, waited_ms와 주기 저장값을 assert한다. 없는 UI 노드나 기본값으로 검증을 통과시키지 않는다.
